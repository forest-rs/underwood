# Source-complete projected text review

- **Date:** 2026-07-24
- **Bead:** `und-oh0.13.3`
- **Design:** Design-0014, Design-0015, ADR-0005
- **Scope:** compact projection algebra, real whitespace collapse, public
  preparation integration, source-correct scene lowering

## Result

Underwood now has one reusable `no_std + alloc` projection kernel independent
of documents, scenes, paint, shaping, and widgets. `ProjectedText` owns the
authored string, an optional presentation string, and compact ordered
`ProjectionSegment` runs. `ProjectionBuilder` validates complete monotonic
authored coverage and UTF-8 boundaries.

The relation vocabulary is executable rather than schematic:

| Relation | Authored interval | Presentation interval |
| --- | --- | --- |
| identity | nonempty | identical nonempty bytes |
| replacement | nonempty | nonempty transformed bytes |
| collapse | nonempty | nonempty collapsed unit |
| omission | nonempty | empty boundary |
| insertion | empty boundary | nonempty generated bytes |

Identity, many-to-one, one-to-many, many-to-zero, and zero-to-many fixtures
exercise both mapping directions. Interior replacement/collapse positions use
affinity: downstream selects the before side and upstream selects the after
side. An omission boundary similarly exposes both authored sides. Selecting
any visible part of one transformation unit maps to the complete authored
unit.

## Real preparation path

`ParagraphStyle::whitespace_collapse` now drives projection before Unicode
analysis. The default is `Preserve`, so existing documents and callers retain
their exact behavior. `Collapse` recognizes CSS document whitespace—space,
tab, carriage return, line feed, and form feed—and replaces each maximal run
with one ASCII space. It deliberately does not yet trim paragraph or line
edges.

Projection sees the complete paragraph stream. A test splits five whitespace
bytes across two semantic leaves with different paint styles. Parley shapes
one display space; its interaction unit and glyph provenance map back to both
leaf-local authored ranges; logical selection selects both ranges; and the
first authored contributor owns semantic/style/paint selection. This proves
that the behavior is not leaf-local preprocessing or a benchmark-only
facsimile.

The scene composes two explicit maps:

```text
snapshot/composition leaf-local source
              ↕
flat authored paragraph stream
              ↕
ProjectedText presentation stream
              ↓
analysis / shaping / line formation
```

Carets map through affinity, interaction and glyph ranges map through complete
source intervals, and semantic ownership uses the first authored contributor.
The formation cache key includes both maps, so identical presentation text
cannot reuse geometry carrying different provenance.

All pre-existing Parley interaction tests remain green, including extended
graphemes split across leaves, ligatures, CRLF, mixed bidi, Arabic line-final
reshaping and marks, controls, empty text, selections, and composition epochs.

## Representation and allocation proof

The label wind tunnel has isolated projection scenarios measured in an
optimized build. Each timing run performed 1,000,000 operations; three local
runs produced:

| Scenario | ns/operation |
| --- | ---: |
| identity | 10, 10, 10 |
| dense collapse | 53, 52, 52 |
| one-to-many expansion | 50, 50, 49 |

`MallocStackLogging=full` plus `malloc_history -allEvents`, subtracting a
matched source-setup process, reported:

| Scenario | allocation calls | requested bytes |
| --- | ---: | ---: |
| identity | 0 | 0 |
| dense collapse | 2 | 88 |
| one-to-many expansion | 2 | 88 |

Identity moves the authored `String` without copying it and synthesizes its one
observable relation run from the known length. Nonidentity cases allocate one
presentation string and one relation-run buffer. A 32,768-byte identity
fixture and a 32,768-byte dense-whitespace fixture each expose one relation
run. There is no per-byte map.

Running the complete allocation matrix after integration reproduced the
pre-projection public-path baselines exactly: cold preparation remained 542
allocation calls/130,464 bytes, retained and paint-only preparation remained
247/26,640, localized editing remained 739/158,317, width/region churn remained
181/25,592, and identity churn remained 1,009/225,921. Preserve mode therefore
adds no allocation or retained-cache footprint to existing preparation.

Commands:

```sh
cargo run --release -p underwood_label_benchmark -- projection-identity 1000 1000
cargo run --release -p underwood_label_benchmark -- projection-collapse 1000 1000
cargo run --release -p underwood_label_benchmark -- projection-expansion 1000 1000
benches/labels/profile-allocations.sh
```

The allocation script cleans up held processes; a subsequent process-table
inspection found no `underwood_label_benchmark` process.

## Public migration

This is an additive pre-stable API change. Existing `ParagraphStyle::new`
calls remain source-compatible and preserve authored whitespace. Callers that
want collapse add:

```rust
ParagraphStyle::DEFAULT
    .with_whitespace_collapse(WhitespaceCollapse::Collapse)
```

Hosts with their own transformation stage may use `ProjectedText` and
`ProjectionBuilder` without constructing an Underwood document or scene.
There is no compatibility shim that rewrites authored text in place.

## Honest boundary

This slice does not claim complete CSS whitespace conformance. Edge trimming,
line-context hanging behavior, tabs as advance policy, language-sensitive text
transformation, wrapping, line breaking, spacing, and justification belong to
later stages in Design-0014 and Design-0015. The important completed boundary
is that those stages can now consume presentation text without sacrificing
authored editing or provenance.
